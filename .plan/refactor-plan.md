# Refactor: FastHTML → FastAPI + Astro (Mosaic Lite-styled) on Railway

> **Updated after extended CEO review (UC-2 + UC-4 accepted):**
> - **UC-2:** SEO is top priority; every page pre-rendered to static HTML at build time.
> - **UC-4:** Stack switched from Vue 3 SPA → **Astro + FastAPI**. Astro ships 0 KB JS by default, each page pre-rendered as static HTML, interactive bits added as "islands" (Vue/Preact/Svelte components that hydrate on demand). Matches the competitive genre pattern (Dakar, HEWC, Supercross, MXGP all SSR). Removes two of three top risks (SEO regression + pre-render-DB-at-build dance).
> - **URL prefix `/app/` removed.** Astro's file-based routing serves every page at the root path — existing URLs (`/2026/expert`, `/2026/r/42/john-doe`) preserved exactly. No backward-compat redirects needed.
> - **Mosaic Lite Tailwind components still in play** — reused as styled markup inside Astro `.astro` files. Tailwind config + dark palette + motorsport-identity guardrails unchanged.
> - **Success metrics locked in:** LCP + JS bundle size (perf), organic search sessions + indexed pages (SEO), visits/week + mobile share (traffic), time-to-ship-next-feature (business case).
>
> See `.plan/ceo-review.md` for full reasoning and competitive analysis. See `.plan/design-review.md` and `.plan/eng-review.md` for findings still applicable under Astro.

## Context

The app today is **FastHTML** (python-fasthtml), not FastAPI. Pages are generated by Python DSL (`Div`, `Table`, `Tr`, …) in `src/ui/`, with CSS embedded inline in `src/ui/styles.py`. There is no JavaScript, no templates dir, no build step, and no JSON API. Data is Postgres via SQLAlchemy 2 + Alembic. Deployment is a single Docker container on Railway.

The refactor splits the stack cleanly:

- **Backend** becomes a pure FastAPI JSON API under `/api/*`.
- **Frontend** becomes an **Astro** site (`/frontend`), styled with Tailwind + cherry-picked Mosaic Lite components, themed dark with gold/silver/bronze podium accents. Every page is static HTML generated at build time (SSG). Interactive widgets — category pill switcher, standings filters, rider comparison, charts — are **Astro islands** hydrated with Vue or Preact only where needed.
- **Deployment** stays a single Railway service: the Dockerfile builds Astro → static `dist/`, copies `dist/` into the Python image, and FastAPI serves it from the filesystem. Dynamic routes (e.g., rider profiles) are enumerated via FastAPI `/api/seasons/{year}/riders` at build time using Astro's `getStaticPaths`, generating one HTML file per rider.

Why: the current FastHTML layer couples rendering to Python and makes rich interactivity (filters, live search, charts, mobile polish) expensive. Moving to JSON + Vue unlocks a modern UI and keeps the existing database, migrations, services, and importers intact.

**How Astro routing works here (file-based + `getStaticPaths`):**
- Pages with bracketed segments (`[year].astro`, `[category].astro`) are dynamic templates.
- Each page exports `getStaticPaths()` which calls FastAPI at build time to enumerate valid combinations:
  - `[year]/[category].astro` fetches `/api/seasons/{year}/standings/{cat}` for each (year × category) → emits one static HTML per pair.
  - `[year]/r/[raceNumber]/[slug].astro` fetches `/api/seasons/{year}/riders` for each year → emits one HTML per rider.
  - `[year]/events/[slug].astro` fetches `/api/seasons/{year}/events` → one HTML per event.
- Build output: `frontend/dist/2026/expert/index.html`, `frontend/dist/2026/r/42/john-doe/index.html`, etc.
- **No pre-render scope list to maintain** — Astro discovers routes automatically from the API.

## Domain rule — rider identity

A rider is uniquely identified within a season by the tuple **`(race_number, first_name, last_name)`** — not by `race_number` alone. Race numbers can be reused across different people (common when riders share a number across categories, or when a number is reissued). This is already reflected in the current code:

- `services/rider.py::get_rider_profile(session, season, race_number, first, last)` takes all three fields.
- `services/rider.py::riders_sharing_number()` returns a disambiguation list.
- The current URL `/r/{race_number}/{slug}` uses a name-derived slug as the second key.

Implications for this refactor:

1. **API path keys.** `/api/seasons/{year}/riders/{race_number}` returns a list (disambiguation); `/api/seasons/{year}/riders/{race_number}/{slug}` is the singular resource. The slug MUST be deterministic from `first_name + last_name` (e.g., `slugify(f"{first} {last}")`) and stable across events/categories so deep links don't rot mid-season.
2. **Pydantic schemas.** The `Rider` response model exposes `{ race_number, first_name, last_name, slug, team?, bike? }`. Any rider identifier in nested payloads (e.g., a row in `StandingsRow`) must include `slug` alongside `race_number`, never just `race_number`.
3. **Frontend routing.** Links to a rider always build `/app/{year}/r/{race_number}/{slug}`. If code ever has only the number, it routes to the disambiguation view first.
4. **DB schema (verify, don't change yet).** Confirm the existing `Rider` table stores rows keyed compatibly with this rule. Current model note from exploration: `Rider [season + category unique]` on `race_number`, which means the same person in two categories is currently two `Rider` rows. That's fine for this refactor — the service layer already joins across categories in `get_rider_profile`. A future cleanup could introduce a `Person` entity (one row per `(season, race_number, first, last)`) with category memberships, but that is **out of scope here**.
5. **Tests.** Add an API contract test that exercises the disambiguation case: seed two riders sharing `(year, race_number)` but differing in names; hit `/api/seasons/{year}/riders/{race_number}` and assert the list; hit both slug URLs and assert the right profiles.

## Considerations (comprehensive)

### 1. Framework migration (FastHTML → FastAPI)

- `python-fasthtml` is removed entirely. All 11 current routes in `backend/src/routes.py` must be split into (a) JSON endpoints under `/api/*` and (b) Vue views that call them.
- Response shapes are designed from the service layer outward. `services/standings.py` and `services/rider.py` already return Python objects (`StandingsRow`, rider profile dicts) — wrap them in Pydantic schemas, don't rewrite.
- Visit tracking (`src/database.py`) moves to a FastAPI middleware that only records when `Accept: text/html` AND path starts with `/app/` (not API calls) to preserve current analytics semantics.

### 2. API design

One endpoint per resource, URL-addressable and cacheable. Proposed contract:

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/seasons` | List all seasons with `is_current` flag |
| GET | `/api/seasons/{year}` | Season meta + categories + events |
| GET | `/api/seasons/{year}/standings` | All categories (for tab preview) or redirect |
| GET | `/api/seasons/{year}/standings/{category}` | Full standings table for one category |
| GET | `/api/seasons/{year}/events` | Event calendar |
| GET | `/api/seasons/{year}/events/{slug}` | Event meta (for overview page) |
| GET | `/api/seasons/{year}/categories/{cat}/events/{slug}` | Event results |
| GET | `/api/seasons/{year}/riders/{race_number}` | Rider list if multiple share number |
| GET | `/api/seasons/{year}/riders/{race_number}/{slug}` | One rider across categories |
| GET | `/api/stats` | Visit analytics |
| GET | `/health` | Health check (unchanged) |

All endpoints are `GET` and cacheable. Return Pydantic v2 models with `from_attributes=True` for ORM compatibility.

### 3. Backward compatibility (fully preserved under Astro)

Astro's file-based routing emits static HTML at the **exact URL paths the current FastHTML app serves**:
- `/2026/expert` → `dist/2026/expert/index.html`
- `/2026/r/42/john-doe` → `dist/2026/r/42/john-doe/index.html`
- `/2026/events` → `dist/2026/events/index.html`
- `/stats` → `dist/stats/index.html`

**No redirects needed.** Every existing shared link, bookmark, social share, and Google search result continues to resolve. Slug algorithm is pinned (Eng review CQ-1) so rider URLs are byte-identical to current.

Only FastAPI-level change: mount `StaticFiles(directory="frontend_dist", html=True)` at root AFTER `/api/*` routers + `/health`. The `html=True` flag makes `/2026/expert` resolve to `/2026/expert/index.html` transparently.

### 4. Mosaic Lite + dark theme

Mosaic Lite is a **Tailwind 3+** admin template (Cruip, free tier available). Integration plan:

- Install Tailwind, configure `darkMode: 'class'`, set `<html class="dark">` by default.
- Copy the Mosaic Lite components we actually use (Sidebar, Topbar, Card, Table, Stat widgets) into `frontend/src/components/mosaic/` — don't vendor the whole template; cherry-pick.
- Override the palette in `tailwind.config.js`:
  - `primary`: gold/amber (current `#f59e0b`/`#fbbf24`)
  - `slate`/`gray` retuned toward the current `#0b0d10`/`#14171c` elevated-surface system
  - Add `podium-gold`, `podium-silver`, `podium-bronze` for position badges
- **Licensing**: verify Mosaic Lite free-tier license permits component extraction. Mosaic Lite (free) is MIT-licensed in its Cruip repo; Mosaic (pro) is not. Use only components from the free repo.

- Backend dev: `cd backend && uvicorn app.main:app --reload --port 5001`.
- Root `Makefile` or `justfile` with `make dev` that runs both in parallel (via `concurrently` or `tmux`).
- Keep `start.sh` for the "just run the whole thing locally" case; update it to run the built frontend.

### 7. Testing

- **Backend**: keep `tests/test_standings_2025.py` (golden test over CSV import — critical). Add `tests/test_api.py` with FastAPI `TestClient`: assert schema, status codes, one happy-path per endpoint. Target: every API endpoint has one contract test.
- **Frontend**: Vitest for component unit tests (PositionBadge, PointsPill, TimeCell — pure rendering). Playwright (or Cypress) for one smoke e2e that boots the real backend against a seeded test DB.
- CI: GitHub Actions workflow runs `pytest`, `vitest run`, `npm run build` (catches TS/build errors).

### 8. Performance & caching

- API responses are all read-only and keyed by URL — set `Cache-Control: public, max-age=60, s-maxage=300` on `/api/seasons/*` endpoints. Railway sits behind Cloudflare-ish edge by default.
- Vite bundle: set `build.rollupOptions.output.manualChunks` to split vendor (vue, vue-router, pinia) from app code for better long-term caching.
- Static assets from `dist/` served with long cache + hashed filenames (Vite default).

### 9. SEO and social sharing (fully solved by Astro SSG)

Current site is crawlable (server-rendered HTML). Astro SSG is the same model — every page is pre-generated to static HTML at build time. **No SEO regression possible** for any route Astro emits.

**Astro SSG coverage:**

| Route pattern | How Astro generates | Emit at build? |
|---|---|---|
| `/` (bare landing) | Static `src/pages/index.astro` redirect | Yes |
| `/{year}` | `getStaticPaths` enumerates from `/api/seasons` | Yes (per year) |
| `/{year}/{category}` (standings) | `getStaticPaths` enumerates from `/api/seasons/{year}` | Yes (per year × category ≈ 16) |
| `/{year}/events` | `getStaticPaths` enumerates from `/api/seasons` | Yes (per year) |
| `/{year}/events/{event_slug}` | `getStaticPaths` fetches `/api/seasons/{year}/events` | Yes (per event × year ≈ 8-16) |
| `/{year}/{category}/{event_slug}` (results) | `getStaticPaths` fetches `/api/seasons/{year}/events` × categories | Yes (bounded: ~128 HTML files at current data) |
| `/{year}/r/{race_number}/{slug}` (rider) | `getStaticPaths` fetches `/api/seasons/{year}/riders` for each year | Yes (one HTML per rider ≈ 300-500 files) |
| `/stats` | Static `.astro` page with noindex meta + auth gate | Yes (but robots:noindex,nofollow) |

**All routes ship as static HTML.** Total build output: ~500-700 HTML files at current data scale. Every page Googlebot ever requests is static HTML with `<title>`, `<meta description>`, `<link canonical>`, `og:title`, `og:image`, Twitter cards already populated. Zero JS required for indexing.

**Build-time API dependency:**
- Astro calls FastAPI at build time. In CI this means FastAPI must be reachable during `npm run build`.
- Solution: Docker's frontend-build stage boots a temp uvicorn instance + Postgres (via docker-compose in CI) OR calls a deployed dev/staging API. Simplest: **run the build in the same container stage as FastAPI + Postgres running in background**, shut down after. Clean pattern documented in Phase 4.
- Alternative: export a single `routes.json` snapshot from prod periodically, commit it, Astro reads the snapshot. Falls back to this if CI-side DB proves annoying.

**Rollback criterion:** capture 4-week baseline organic traffic before launch (Search Console). If post-launch traffic drops >25% sustained for 14 days, investigate indexing — but since every URL emits static HTML, a regression is unlikely unless a routing bug breaks canonical URLs.

**Islands + SEO:** interactive islands (e.g., StandingsFilter) hydrate client-side AFTER initial HTML paint. Search crawlers see the static pre-island HTML → indexing is based on pre-hydrated content. No SEO cost for adding islands later.

### 10. Accessibility

The current CSS has decent contrast and large tap targets. Preserve:
- Keyboard navigation for category tabs and year switcher (ARIA `role="tab"`, `aria-selected`).
- Focus rings (Tailwind `focus-visible:` with accent color).
- `prefers-reduced-motion` respected for any transitions.
- Position badges must not rely on color alone — keep the numeric text (already does).

### 11. Internationalization

Seed CSV headers are Bulgarian (`Поз`, `Ст.№`, `Състезател`). The UI is currently English. The refactor is a good moment to decide:
- Leave as English-only (simplest, matches current).
- Add vue-i18n with `en` + `bg` dictionaries (small cost now, saves pain later).

Recommend **English-only unless bilingual is a stated product goal** — defer i18n to a separate scope.

### 12. Visit tracking privacy

Current tracking records page + category + device type + timestamp, no PII. Keep it, but:
- Move recording to a background task (`BackgroundTasks`) so it never blocks response.
- Exclude `/api/*` from tracking; track only `/app/*` visits where `Accept` includes `text/html` (initial SPA load), OR add a one-line `POST /api/track` call from the Vue router's `afterEach` hook for per-route tracking. Recommend the latter — it matches the current per-page semantics.

### 13. Migration / cutover strategy

Two workable approaches:

**A. Big-bang on a branch (recommended for a solo/small team):**
Build the full FastAPI + Vue stack on a feature branch, test end-to-end with a Railway preview deployment, then swap in one PR. Fastest, lowest complexity, acceptable for a read-only dashboard with no user sessions.

**B. Strangler pattern:**
Run both apps side-by-side (FastHTML on port A, FastAPI on port B), gradually move routes. Overkill here — no persistent user state, no background jobs, no sessions to migrate.

**Recommend A.**

### 14. Risk register

| Risk | Mitigation |
|---|---|
